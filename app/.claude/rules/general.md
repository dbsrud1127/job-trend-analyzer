# General Rules

## 우선순위
- 화려함보다 "완전히 동작하는 것"이 먼저다.
- 순서: 핵심 완성 → 배포 → 추가 기능. 항상 동작하는 배포 링크를 유지한다.
- 작업 순서는 CLAUDE.md "4. AI 사용 원칙"을 따른다.

## 초보자 기준
- 사용자는 비전공 초보자다 (if, 반복문, 함수, 클래스를 혼자 작성하기 어려움).
- 코드는 복사해서 바로 쓸 수 있게, 줄마다 한국어 주석을 단다.
- 처음 나오는 문법은 한두 줄로 설명한다.
- 복잡한 추상화, 디자인 패턴, 과한 설계는 쓰지 않는다. 과하다 싶으면 먼저 지적한다.
- 새 라이브러리를 제안할 때는 학습 비용과 남은 일정을 함께 말한다.

## 보안
- .env 는 절대 커밋하지 않는다. 비밀값(DB 비밀번호, API 키)은 코드에 직접 쓰지 않고 환경변수로 읽는다.
- GitHub Actions / Render 에서는 Secrets / Environment Variables 로 넣는다.

## Git
- 커밋은 기능 단위로 작게. 메시지는 한글/영어 모두 가능, 무엇을 했는지 명확하게.
  예: `feat: remotive 수집기 추가`, `fix: 태그 소문자 변환 누락 수정`
- 커밋 전 `git status` 로 .env 가 목록에 없는지 확인한다.
